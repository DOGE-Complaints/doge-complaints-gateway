## Task: analyze — сквозной pipeline Epic -> Story -> Execution для Module 2

### Источники процесса (обязательные)
1. Эпики M2: `doge-complaints-gateway/docs/tasks/epics/`
2. Декомпозиция эпика: `@.cursor/commands/bullrun-epic-decompose.md`
3. Выполнение стори: `@.cursor/commands/bullrun-start.md`
4. Обязательное мышление анализа (always-on): `@.cursor/rules/analysis.mdc`
5. Обязательный skill Python-реализации стори: `@.cursor/skills/sources/jeffallan-claude-skills/skills/python-pro/SKILL.md`

### Контракт ролей в пайпе
- `bullrun-epic-decompose` — **разовый процесс** для уровня Epic (создание/обновление Story-структуры и task-папок).
- `analysis.mdc` — **обязательное мышление**, которое применяется совместно с разовыми процессами пайпа (в первую очередь вместе с `bullrun-epic-decompose`).
- `bullrun-start` — **процесс выполнения Story** (по фазам и с артефактами).
- `python-pro` — **skill**, который должен явно заявляться и применяться при выполнении Python Story.

### Цель
Сформировать и зафиксировать единый рабочий pipeline, который масштабируется на все уровни M2:
- `Epic` (описан, статусируется, готов к декомпозиции);
- `Story` (создается по стандартизированному процессу и имеет task-папку);
- `Execution` (каждая стори выполняется по фазам с логами, AC-верификацией и управляемыми decision points).

### Почему это важно (риск)
Без единого пайпа возникает рассинхрон между эпиками, стори и фактическим исполнением: статусы в индексах, артефакты по фазам, критерии приемки и правила работы с Python-кодом могут расходиться.

### Out of Scope
- Реализация бизнес-функциональности конкретных сторис M2.
- Коммиты по незавершенным стори (в рамках этой meta-задачи).

### Факты из текущего состояния
1. В `EPIC-M2-01` уже есть связка `Epic -> Stories` с явными ссылками на task-артефакты.
2. В `docs/tasks/` уже применяется формат task-папок `task-m2-...` с файлами `README.md`, `BULLRUN-PHASE-LOG.md`, `acceptance-verification-...`.
3. Команда `bullrun-start` закрепляет запуск стори через `run-task` и работу по фазам с обновлением bullrun-индекса.
4. Команда `run-analysis` закрепляет порядок этапов, обязательную верификацию AC и чекпоинт при остановке.

- [ ] Зафиксирован единый контракт артефактов для каждого уровня (какие файлы обязательны и где лежат).
- [ ] Зафиксированы правила смены статусов и синхронизации с `docs/tasks/bullrun-launch-index.md`.
- [ ] Зафиксирован контракт ролей: где процесс, где мышление, где skill.
- [ ] Зафиксирован стандарт исполнения Story: процесс `bullrun-start` + skill `python-pro`.
- [ ] Подготовлен операционный чеклист запуска новой стори из эпика.
- [ ] Подготовлен шаблон проверки качества процесса (phase log + acceptance verification).

### Где менять код/доки в рамках задачи
- `doge-complaints-gateway/docs/tasks/epics/*.md` (при уточнении статусов и структуры декомпозиции)
- `doge-complaints-gateway/docs/tasks/bullrun-launch-index.md` (при необходимости синхронизации процесса)
- `doge-complaints-gateway/docs/tasks/task-m2-epic-story-pipeline/*` (рабочие артефакты meta-задачи)

### План выполнения (по методике)
1. **Анализ (мышление `analysis.mdc`)**
   - Сверить все эпики M2 и текущее состояние декомпозиции.
   - Зафиксировать gap между "как задумано" и "как реально выполняется".
2. **Решения**
   - Зафиксировать decision points по правилам декомпозиции и запуска сторис.
   - Явно зафиксировать контракт: `process + thinking` для Epic и `process + skill` для Story.
3. **Архитектура процесса**
   - Описать целевой workflow и точки контроля качества.
4. **План реализации процесса**
   - Определить, какие шаблоны/доки и в каком порядке обновляем.
5. **Реализация процесса**
   - Внести изменения в документы и шаблоны пайпа.
6. **Квалификация**
   - Проверить воспроизводимость процесса на примере одной новой/пустой стори.
7. **Верификация AC**
   - Заполнить `acceptance-verification-task-m2-epic-story-pipeline.md`.

### Операционный чеклист запуска (черновик)
1. Выбрать Epic со статусом `Draft/In Progress` и целевой Story для запуска.
2. Для декомпозиции Epic использовать `bullrun-epic-decompose` совместно с `analysis.mdc`.
3. Убедиться, что у Story есть task-папка с `README.md`, `BULLRUN-PHASE-LOG.md`, `acceptance-verification-*.md`.
4. Запустить выполнение Story через `bullrun-start`.
5. Явно заявить и применять skill `python-pro` во время Python-реализации.
6. Вести фазы, обновлять статусы и синхронизировать `docs/tasks/bullrun-launch-index.md`.
