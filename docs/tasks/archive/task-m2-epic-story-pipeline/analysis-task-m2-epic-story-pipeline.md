## Проверенные факты (только из репозитория)
1. В `EPIC-M2-01-core-foundation-and-governance.md` есть раздел `Stories (decomposed)` и реальные файлы сторис `STORY-M2-01-01..04`.
2. В остальных эпиках M2 (`EPIC-M2-02..10`) статус `Draft`, и в них пока только `Initial Story Decomposition (Draft)`, без отдельных файлов `stories/STORY-...`.
3. В сторис `M2-01-01..04` присутствует блок `Task Artifacts` со ссылками на `task-m2-*` папки, `BULLRUN-PHASE-LOG.md` и `acceptance-verification-*.md`.
4. В `docs/tasks/` существуют task-папки только для `M2-01-01..04` и текущей meta-задачи `task-m2-epic-story-pipeline`.
5. `docs/tasks/bullrun-launch-index.md` содержит только секцию `EPIC-M2-01`; строки для `EPIC-M2-02..10` отсутствуют.
6. В постановке meta-задачи уже зафиксирован контракт ролей:
   - Epic-декомпозиция: `bullrun-epic-decompose`;
   - always-on мышление: `analysis.mdc`;
   - Story execution: `bullrun-start`;
   - Python execution skill: `python-pro`.

## Gap analysis
1. **Неполная сквозная операционализация по всем эпикам M2.**
   - Фактически процесс развернут только на `EPIC-M2-01`.
   - Для `EPIC-M2-02..10` нет созданных story-файлов и task-папок.
2. **Отсутствует единый runtime-чеклист на уровне общей зоны `docs/tasks/`.**
   - В постановке задачи чеклист есть, но он еще не вынесен в отдельный канонический файл процесса для повторного использования.
3. **Не синхронизирована индексация уровня Epic в `bullrun-launch-index.md`.**
   - Индекс отражает только один эпик, что затрудняет сквозной трекинг пайпа "по всем уровням".
4. **Не зафиксирована процедурная точка “обязательное объявление skill”.**
   - В мета-задаче требование описано, но пока не закреплено в отдельном контрольном шаге исполнения стори.
