# Decision Points — STORY-M2-02-03

## DP-01: Где хранить idempotency mapping
- Решение: отдельный `IdempotencyRepository` контракт.
- Причина: чистое разделение ответственности и возможность сменить backend в pilot.

## DP-02: Поведение при повторе ключа
- Решение: возвращать уже созданный `StoryRecord` без создания нового.
- Причина: детерминированность и безопасность повторов клиентских ретраев.

## DP-03: API уровня конфликта
- Решение: для baseline одинаковый ключ всегда возвращает существующий результат.
- Причина: упрощенный predictable flow для demo стадии.
