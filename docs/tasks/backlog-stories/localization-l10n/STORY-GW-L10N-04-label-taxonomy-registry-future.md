## Зачем простыми словами
Сейчас фильтр меток на фронте строится из меток уже загруженных issue — список неполный и «прыгает» при разных выборках. Полный реестр всех канонических ключей меток дал бы стабильный полный фильтр. Фронт **сознательно отложил** это (живёт с неполным фильтром) — поэтому это заглушка на будущее, а не работа на сейчас.

## Что наблюдаю сейчас (verified по коду)
- Губернируемый набор меток на бэке узкий и зашит в enum: `DOGEIssueLabel` = `waste`, `district`, `infrastructure`, `safety` ([enums.py:22-28](../../../../src/core/projection/enums.py#L22-L28)).
- Маппинг канонических токенов → SPA-меток также захардкожен ([extraction_policy.py:57-73](../../../../src/core/projection/extraction_policy.py#L57-L73)).
- Публичного endpoint «список всех меток» нет.
- ⚠️ Набор меток бэка (4) **не совпадает** со словарём фронта `AVAILABLE_LABELS` (10) — см. кросс-доку [STORY-SPA-G3 §5](../../../../../spa-app/docs/tasks/backlog-stories/STORY-SPA-G3-search-input-toolbar.md). Этот рассинхрон стоит учесть, если реестр будет делаться.

## Если/когда понадобится (целевое состояние)
- Публичный endpoint с **полным актуальным списком канонических ключей меток** (для полного, не «прыгающего» фильтра).
- Источник истины реестра — согласовать: enum бэка vs отдельная таблица-словарь vs пересечение с фронтом.

## Условие реактивации

- Неполнота фильтра меток становится проблемой для пользователей: **≥50** label-miss events за 7 дней (GW-L10N-03 telemetry) **или** явный запрос продукта.
- До этого — оставляем ⏸️; фронт живёт с фильтром из данных (L10N-02 на фронте).
