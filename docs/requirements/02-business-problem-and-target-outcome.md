# 02. Бизнес-задача и целевое решение

## Исходная проблема
Прямой поток историй в операционные системы создаёт:
- шум и дубли;
- потерю контекста человека;
- преждевременную фиксацию смыслов;
- слабую пригодность для Smart City / gov контуров.

## Целевая цепочка ценности
`Story -> Signal Profile -> Dynamic Cluster Views -> Distinct Issue -> Dashboard/Evidence Pack`

## Product outcomes
- снижение объёма дубликатов на уровне публичной витрины;
- сохранение доказательной глубины на уровне story/evidence;
- повторная переагрегация corpus без потери данных;
- увеличение доли issue, пригодных для внешней подачи.

## CTO outcomes
- разделение ingestion-потока и витринной проекции;
- поддержка переиндексации/перекластеризации без переписывания первичных данных;
- прозрачная lineage-модель для аудита решений.

## Бизнес-метрики
- Duplicate Compression Ratio;
- Cluster Cohesion Score;
- Issue Readiness Conversion Rate;
- False Merge Rate (неправильные склейки);
- Evidence Completeness Index.

## Риски
- агрессивная дедупликация уничтожает minority-сигналы;
- слабая нормализация создаёт story swamp;
- отсутствие порога зрелости генерирует “шумные issues”.

## Контрмеры
- пороги готовности issue-candidate;
- обязательная human/process review для split/merge;
- аудит качества кластеров по временным окнам.
